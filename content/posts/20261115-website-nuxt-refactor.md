从上一次网站重构日志发布到现在，这个网站又被大规模地重构了一遍。如果说上一篇还算"在原有地基上翻新"，这一次就是整个掀掉重来：技术栈从 VitePress 换成 Nuxt 4 + TypeScript + Tailwind CSS，版式从"顶栏+核心内容+双侧边栏"的 F 型改成"顶栏+核心内容+底栏"的 Z 型，连部署都搬了家。跨度之大，接近在超燃竞技场里中途换英雄——装备、技能、站位全部重配。下面按技术栈、版式、部署、工具、零碎增强五条线来写。

## 一、技术栈重构

这次更换的核心提交，是十月二十五日合并的那次迁移：从 VitePress 换到 Nuxt 4 + @nuxt/content v3 + Nuxt UI 4 + TypeScript + Tailwind CSS v4，构建方式改为 SSG 静态生成。

为什么换？因为原来的技术栈从根上定位就错了。VitePress 本质是文档生成器，目标是把 Markdown 转成好看的文档站，能力天花板从第一行代码就画好了。而这个网站早就不是文档站——博客归档、分类标签、全文搜索、评论区、阅读进度、主题切换，还有一堆需要客户端状态的组件。继续用文档生成器硬撑，等于让辅助位选手去打核心输出：不是不能打，是每一次交锋都在对抗自己的装备。

用竞技场的话说，这是一次换位：从辅助位换到法师位，整套装备跟着重配。新栈里各部件分工很清楚——Nuxt 4 是应用框架和路由的骨架；@nuxt/content v3 把文章变成可查询的数据；Nuxt UI 4 提供顶栏、底栏、卡片、弹窗等组件；TypeScript 把类型安全钉在编译期，让低级错误上线前就暴露；Tailwind CSS v4 用设计令牌统一视觉，颜色、间距、圆角不再手敲数值。

迁移中还夹着一次版本升级：Nuxt 推到 4.6.3，同时移除冗余的 Vue 依赖——Vue 已被 Nuxt 包含，单独声明只会带来版本错配隐患。这类清理不起眼，却是长期稳定的关键。核心思路没变：静态产物的形态不变，能承载的上限变了。

## 二、样式和版式重构

技术栈换了，样式层全面接入 Nuxt UI 4——不是换一批组件，而是把视觉系统交给统一的设计语言托管。以前颜色、间距、圆角散落各处，改一处要翻半天；现在收敛到 @theme 设计令牌，改一个变量，全站跟着变。

版式改动最直观：从"顶栏+核心内容+双侧边栏"的 F 型，改成"顶栏+核心内容+底栏"的 Z 型三段式。旧版靠两侧边栏塞辅助信息，密度看着高，实际是让读者在三条纵向通道间来回切换视线——人的视线根本不是"读"，是"扫"，三条通道只会把注意力撕碎。新版回到正常文档流：顶栏常驻，内容居中，底栏收尾，视野只剩一条主通道。

这套三段式骨架不是我凭空想的，最先来自我自己的一个开源项目官网。那边走的是渐进路线：十月二十一日先把技术栈从文档生成器换成应用框架，隔了十天，到十月三十一日才重构布局与样式、集成样式规范化，换技术栈和换版式分作两步，中间隔着两套东西并存的日子。这个个人站不同——技术栈换完后，接入 Nuxt UI 和换成三段式是在同一次提交里一起完成的，没有过渡态。

节奏为什么不一样？借鉴骨架省掉从零试错，但推进方式得按站点情况定。那个官网历史包袱重、访问量大，适合小步慢走；这个站结构简单，一次切换反而干净，不用长期维护新旧两套样式并存的中间态。同一套骨架，落在不同规模的站点上，打法就该不一样。移动端的两个侧边栏原本都是抽屉菜单，三段式之后这套机制直接取消，路由滚动也交还浏览器，不再自建滚动容器。

这次同时删掉大量冗余代码：左右侧栏、抽屉手势、阅读进度条、.site-main 滚动容器，以及成百上千行为对抗旧框架手写的样式。

这里有个值得单独说的因果。旧版积攒的大量 bug，相当一部分病根就在旧版式本身——三条纵向通道、自建滚动容器、侧栏抽屉联动，几乎每样都是温床。为压住它们，我前后写过一堆补丁：算滚动偏移的、同步抽屉状态的、修正容器高度的，越堆越多。换成三段式后，这些结构的根基没了，之前出现的大量 bug 随之解决；问题不再出现，那些专门为修它们写的冗余代码也就一并删掉。不是我逐个修好的，是结构一改，问题自己就不成立——跟竞技场里拆掉一个不合理站位一个道理。首页重做为七个区块：Hero、关于我与身份主线、最新日志、长期维护的项目、游戏 ID 跑马灯、工具矩阵、关于站点；文章卡片统一成"封面+标题/分类·日期/摘要"，详情页去掉卡片外壳。

细节打磨举几处：

游戏 ID 跑马灯。这是这次重构才新加的区块，旧版没有——它属于"完整应用"带来的东西，文档生成器做不出这种带状态的动态展示。但第一版就踩坑：不管几张卡都套滚动组件，只有两个号时也左右循环，既看不清名字，又变成一条空白跑道。于是改成按数量判断，超过五张才滚，否则退回静止的横向列表，可键盘聚焦、手动横滑；随后放大卡片、把门槛降到三张，并让窄屏（小于 768px）退化成一行一张的静态网格，消掉横向滚动条。

前面这一连串调整都只是中间形态。从"无条件滚动"到"五张起滚"，再到"三张起滚、卡片放大、窄屏静态"，每步都是拿真实数据喂出来的修正。而落到"三张起滚、卡片放大、窄屏静态网格"的这一版，在目前的 ID 数量和屏幕分布下，是已经调到位、暂时不用再改的最终形态。当然"目前而言"四个字得留着——将来需求变了该调还得调，但现在没有再动它的理由。

主题开关。方形图标按钮换成胶囊形态的三态开关，点击顺序固定为跟随系统→浅色→深色→循环。首帧按跟随系统渲染，挂载后再切到真实模式，避免服务端和客户端渲染不一致。

换版式后仍需单独处理的少数 bug：目录跳转原先双重滚动、正文容器偏移，修成只在正文显式声明时才生成目录；顶部进度条因品牌色变量没定义而透明，补上映射；Hero 底部社交按钮像被渐变盖住，根因是网格底纹的遮罩作用到了所有后代元素，把绘制挪到伪元素上；表格因边框合并变成直角，改成四角圆角；标题去掉链接只留锚点。还引入 Preflight 补齐三套色阶与组件变量映射，并在构建期给正文外链统一加上新标签页打开，禁用 JS 时也生效。

这些都不是凭空新增的功能，而是把原本想要的效果用更短、更稳的路径重新实现——竞技场里管这叫"不亏血量换装备"，输出没变，容错高了。

## 三、网站部署迁移到 Cloudflare Workers

部署也搬了家。之前是 GitHub Pages 外配 Cloudflare CDN 加速，现在一次性迁到 Cloudflare Workers。

旧方案别扭在两套系统叠加：Pages 托管，Cloudflare 在外层加速，要让静态站拿到理想的缓存与跨域行为，得两边各配一遍还得保证不打架；一旦牵涉自定义域名、HTTPS、404 回退，配置就复杂到没人敢动。

迁移后干净得多：一个 assets-only Worker，静态资源直接托管在 Workers 上，自动处理 404 与 HTML 回退；生产与预览部署由 Cloudflare 连接 Git 后自动执行，每个分支拿到独立的 Worker Previews 地址，改版不用先合并就能看效果。GitHub 这边只留一条质量门禁：格式检查、lint、构建、产物校验，任一环不过就别想往下走；本地构建仍可用 wrangler 兜底。

构建链一并重写：先 nuxi generate 生成静态页，再注入字体，最后跑产物断言。关键设置是 nitro 预设锁死 static，防止 Cloudflare 环境变量把预设切成带 Worker 入口的形态，导致产物和部署方式对不上。旧的部署流水线、Pages 专属权限与环境配置全部删除。目标只有一个：把"能跑起来"从依赖一堆外部配置，变成默认就成立。少配一层，就少一处会出错的地方。

## 四、网站工具的迁出

和部署迁移同步，站内工具也搬了家。

原先工具页和首页工具矩阵都在本站，其中还有一个为游戏地图生成文案的小工具——输入地图名和地图码，按规则输出普通版和短视频版文案。这类工具需要不少客户端逻辑，塞在以内容为主的静态站里，等于让法师位去扛近战的活：能扛，但两边都别想发挥。

现在整套工具迁到独立工具站 skystarlight.top，站内不再保留工具路由和清单，顶栏"工具"改为指向外站。导航数据统一成 href + external 结构：外链新标签页打开、自动补安全属性与角标、不参与当前路由高亮；顶栏、移动下拉、底栏三处共用一份数据，改一处全站生效。

这是分工。主站专注内容，工具站专注功能，各自把一件事做到位，比一个站点什么都塞要清楚——远程输出和近战承伤硬塞给同一个角色，通常两边都打不好。

## 五、其他增强

除四条主线外还补了不少细节。

字体改为产物自包含：HarmonyOS Sans SC 的三档分片在构建期灌注进产物，代码字体交给 Vite 打包，不再从 CDN 加载。等于自带补给上场，不依赖地图上的补给站——断网、CDN 抖动、跨域拦截，都不再是正文掉字体的理由。

文章作者支持 frontmatter 自定义，缺省回退到站长；这篇日志署的就是"蛋小蓝"。构建期自动生成网站地图，把文章、归档、分类、标签等路由一次列全，搜索引擎照着抓。产物校验在生成后逐条对账：该渲染的页面有没有漏、静态预设对不对、字体有没有灌注到位——"构建成功"不等于"没有漏页"，漏页在线上就是 404，构建却依然显示绿色，这道校验就是发布前的最后一道防线。搜索弹窗换成 Nuxt UI 的模态组件，开合动画与全站统一，顺手修掉输入框出现两个清除按钮的问题；开发态还启用了框架自带的开发者工具，只在本地生效，生产不打包。

## 结语

从文档生成器到完整应用，从被两侧夹击的 F 型到一条主通道的 Z 型，从借来的托管到自己的基地，从自建工具到独立工具站——这次重构没新增什么惊天动地的功能，做的其实是同一件事：把每一层放回它该在的位置。

系统工程的价值不在某个炫目的功能，而在所有环节对齐之后那种"什么都不用想就能跑"的稳定，这比多写一个特性难得多。最大的收获不是修好了哪个 bug，而是发现一大批老 bug 根本不用修——换掉产生它们的版式，它们自己就消失了，连带那些补丁式的冗余代码一起清干净。下的功夫都在看不见的地方，但每一分都会在最关键的时候兑现。
